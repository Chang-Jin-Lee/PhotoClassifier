# PhotoClassifier 설계

작성일: 2026-09-01

상태: 사용자 승인 설계를 문서화한 구현 전 명세

## 1. 목적

세 명이 촬영한 게임스컴 사진과 영상을 주제별로 통합하여 영상 편집자가 원하는 소스를 빠르게 찾도록 한다. 두 명이 만든 기존 주제 폴더는 학습·참조 자료로 사용하고, `사진`과 `동영상`만 구분한 나머지 한 명의 자료는 로컬 AI로 자동 분류한다.

프로그램의 최종 산출물은 Google Drive에 폴더째 업로드할 수 있는 `편집자전달용` 폴더다. 원본은 읽기 전용으로 취급하며 이동, 이름 변경, 삭제를 하지 않는다.

## 2. 확인된 입력 자료

현재 입력 경로는 다음과 같다.

```text
C:\Users\user\Desktop\게임스컴자료\편집용분류\수집
```

확인 당시 자료 구성은 다음과 같다.

- 기여자: 서주영, 이상민, 이창진
- 사진: JPG 162개
- 영상: MP4 113개
- 총 파일: 275개
- 총 크기: 약 19.6GB
- 이상민과 이창진의 자료: 주제 폴더로 분류됨
- 서주영의 자료: `사진`, `동영상`으로만 구분됨

입력 경로와 기여자 구조는 UI에서 변경할 수 있어야 하며, 위 경로나 사람 이름을 코드에 고정하지 않는다.

## 3. 사용자와 확정한 결정

- 로컬 파일을 대상으로 먼저 구현한다.
- 원본은 보존하고 새 결과 폴더에 복사한다.
- 높은 신뢰도의 분류는 자동 적용하고 애매한 결과만 사람이 검토한다.
- 결과는 `주제/사진`, `주제/동영상` 구조를 사용한다.
- 정확히 동일한 파일은 한 번만 복사한다.
- 비슷한 사진, 연사 사진, 다른 인코딩의 영상은 편집 선택지이므로 자동 제거하지 않는다.
- Google Drive API 업로드와 ZIP 생성은 첫 버전 범위에서 제외한다.
- 완성된 최상위 폴더를 Google Drive의 `폴더 업로드`나 Drive 데스크톱 동기화로 올린다.

## 4. 성공 기준

프로그램은 다음 조건을 모두 만족해야 한다.

1. 입력 폴더의 모든 지원 파일은 `복사 완료`, `정확한 중복으로 복사 생략`, `처리 오류` 중 하나의 최종 상태를 가지며 `분류목록.csv`에 빠짐없이 기록된다. 사용자가 검토를 미룬 파일은 `검토필요` 폴더에 복사 완료된 것으로 센다.
2. 원본 파일의 경로, 이름, 내용, 수정 시각을 변경하지 않는다.
3. 고신뢰도 파일만 자동 분류하며 나머지는 사용자의 결정을 요구한다.
4. 복사된 각 파일은 원본과 SHA-256 해시가 일치한다.
5. 중단 후 같은 작업을 다시 열면 검증이 끝난 복사본은 건너뛰고 이어서 실행한다.
6. 결과 폴더만 Google Drive에 업로드해도 주제 및 미디어 종류별 구조가 유지된다.
7. 영상 편집자가 CSV에서 주제, 촬영자, 촬영 시각, 원본 파일명과 결과 경로를 확인할 수 있다.

## 5. 범위

### 포함

- 입력 구조 검색과 기여자별 분류 상태 자동 추정
- 사용자가 기여자를 `분류됨` 또는 `미분류`로 수정하는 기능
- 폴더명 정규화와 통합 후보 검토
- 사진 분석
- 영상 대표 프레임 추출 및 분석
- 기존 분류 자료를 참조한 로컬 분류
- 신뢰도 기반 자동 분류와 검토 대기열
- 정확한 파일 중복 검출
- 복사 전 실행 계획 미리보기
- 재개 가능한 파일 복사 및 복사본 검증
- 편집자용 폴더와 CSV·텍스트 보고서 생성

### 제외

- Google Drive API 인증 및 자동 업로드
- ZIP 또는 분할 압축 파일 생성
- 원본 파일 이동·삭제·이름 변경
- 유사 사진 또는 유사 영상의 자동 삭제
- 얼굴 인식으로 촬영자나 등장인물을 식별하는 기능
- 인터넷 서비스에 사진이나 영상 내용을 전송하는 기능
- 범용 모델 재학습이나 GPU 전용 학습 파이프라인

## 6. 권장 기술 구조

프로그램은 Windows에서 실행하는 Python 애플리케이션으로 만든다. 백엔드는 로컬 호스트에만 바인딩되는 HTTP 서버이고, 사용자는 자동으로 열린 브라우저 화면에서 작업한다. 별도 프런트엔드 빌드 체인은 두지 않고 서버가 정적 HTML, CSS, JavaScript를 제공한다.

구성 요소는 다음 책임으로 분리한다.

1. **스캐너**: 파일과 폴더를 읽고 미디어 종류, 크기, 수정 시각, 출처자, 기존 주제를 수집한다.
2. **정규화기**: Unicode, 공백, 대소문자, 구분 기호를 정리해 폴더명 통합 후보를 만든다.
3. **미디어 분석기**: 사진을 읽고 영상에서 대표 프레임을 추출한다.
4. **특징 추출기**: 로컬 비전 임베딩과 선택적 문자 인식 결과를 생성한다.
5. **분류기**: 기존 주제별 참조 특징과 미분류 파일을 비교하고 신뢰도 및 근거를 계산한다.
6. **검토 서비스**: 폴더명 통합 후보와 저신뢰도 파일을 사용자에게 제시하고 결정을 저장한다.
7. **계획 생성기**: 중복, 파일명 충돌, 대상 경로, 필요한 용량을 계산한다.
8. **복사 실행기**: 파일을 복사하고 해시를 검증하며 중단 가능한 진행 상태를 저장한다.
9. **보고서 생성기**: 편집자용 CSV와 안내 문서를 만든다.

각 구성 요소는 파일 시스템, 모델, UI에서 분리된 인터페이스를 사용한다. 이 경계는 추후 로컬 파일 시스템 대신 Google Drive 어댑터를 추가할 수 있게 하지만, 첫 버전에는 로컬 어댑터만 구현한다.

## 7. 작업 데이터와 상태

한 작업은 다음 상태를 가진다.

```text
생성 → 스캔됨 → 폴더명검토 → 분석중 → 분류검토 → 계획확정 → 복사중 → 검증완료
```

작업 상태와 사용자 결정은 SQLite에 즉시 저장한다. 상태 파일은 결과 폴더의 `.photoclassifier/state.sqlite3`에 둔다. CSV는 작업이 완료될 때 상태 데이터로부터 다시 생성할 수 있어야 한다.

파일 식별자는 단순 경로가 아니라 `원본 절대경로 + 크기 + 수정시각 + SHA-256`을 사용한다. 원본이 작업 도중 바뀌면 해당 파일을 다시 분석하고 기존 승인을 무효화한다.

## 8. 폴더명 통합 규칙

다음 정규화 결과가 같으면 자동 통합할 수 있다.

- 앞뒤 공백 제거
- 연속 공백을 하나로 축소
- Unicode NFC 정규화
- 영문 대소문자 무시
- `_`, `-`, 공백의 표현 차이 정규화
- 폴더명 끝의 불필요한 구분 기호 제거

정확히 같은 이름인 `넥서스아니마`, `실버팰리스`는 자동 통합 대상이다. 반면 `KOCCA 한국 공동관`과 `한국공동관인터뷰`처럼 핵심 단어는 겹치지만 촬영 목적이 다를 수 있는 이름은 자동 통합하지 않는다. 의미상 유사한 이름은 후보로만 표시하며 사용자가 대표 폴더명을 선택한다.

사용자가 정한 별칭은 작업 상태에 저장하고 같은 실행 안의 모든 파일에 일관되게 적용한다.

## 9. 미디어 분석과 분류

### 사진

- EXIF 촬영 시각과 이미지 방향을 읽는다.
- 방향을 보정한 미리보기와 비전 임베딩을 만든다.
- 문자 인식 기능을 사용할 수 있으면 게임명과 부스 간판을 보조 근거로 사용한다.

### 영상

- 영상 길이와 회전 정보를 읽는다.
- 시작과 끝의 전환 구간만 보지 않도록 전체 구간에서 균등하게 대표 프레임을 추출한다.
- 짧은 영상은 최소 3장, 긴 영상은 최대 12장의 프레임을 사용한다.
- 검은 화면이나 심하게 흐린 프레임은 품질 점수로 제외한다.
- 유효 프레임의 임베딩을 집계하되, 영상 안에서 주제가 바뀌는 정황이 있으면 검토 대상으로 보낸다. 첫 버전은 하나의 영상을 여러 파일로 분할하지 않는다.

### 분류 근거

분류 점수는 다음 신호를 결합한다.

- 같은 주제의 기존 사진·영상 프레임과의 시각적 유사도
- 주제별 중심 임베딩과의 거리
- 문자 인식 결과와 정규화된 주제명의 일치도
- 촬영 시각상 앞뒤 파일의 확정된 주제
- 가장 높은 후보와 두 번째 후보 사이의 점수 차이

모델의 원시 점수를 곧바로 확률로 표시하지 않는다. 자동 분류 기준은 기존 분류 자료를 일부 가린 교차 검증 결과로 보정한다. 기준 점수와 1·2위 차이를 모두 통과한 경우에만 `고신뢰도`로 자동 배정한다. 한 조건이라도 통과하지 못하면 `검토필요`가 된다.

새로운 주제는 기존 자료와 충분히 비슷하지 않으므로 자동으로 임의의 기존 폴더에 넣지 않는다. 사용자는 검토 화면에서 새 주제명을 만들 수 있다.

## 10. 검토 화면

브라우저 UI는 다음 순서로 구성한다.

1. **원본 선택**: 입력 폴더와 결과 상위 폴더를 선택한다.
2. **구조 확인**: 기여자와 `분류됨`·`미분류` 추정 결과를 수정한다.
3. **폴더명 정리**: 자동 통합 결과와 의미상 유사 후보를 승인하거나 분리한다.
4. **분석 진행**: 파일 수, 처리 속도, 예상 남은 항목을 표시한다.
5. **분류 검토**: 썸네일 또는 영상 미리보기, 추천 주제, 대안, 분류 근거를 표시한다.
6. **일괄 처리**: 촬영 시각이 인접한 여러 파일을 선택해 한 번에 같은 주제를 지정한다.
7. **실행 계획**: 대상 폴더별 파일 수와 크기, 중복, 충돌, 오류, 필요한 공간을 보여준다.
8. **복사 및 검증**: 파일별 진행 상태와 실패 원인을 보여준다.
9. **완료**: 결과 폴더 열기와 보고서 열기 기능을 제공한다.

검토 화면의 기본 정렬은 촬영 시각이다. 사진은 큰 썸네일로, 영상은 대표 프레임 묶음과 재생 기능으로 확인한다. 사용자가 결정을 미룬 파일은 `검토필요/사진` 또는 `검토필요/동영상`으로 복사할 수 있다.

## 11. 결과 구조와 파일명

결과 폴더명에는 실행 시각을 넣어 기존 결과를 덮어쓰지 않는다.

```text
편집자전달용_20260901_210000/
  넥서스아니마/
    사진/
    동영상/
  실버팰리스/
    사진/
    동영상/
  검토필요/
    사진/
    동영상/
  분류목록.csv
  중복파일.csv
  처리오류.csv
  README_편집자용.txt
  .photoclassifier/
    state.sqlite3
```

원본 파일명은 유지한다. 같은 결과 폴더에 이름은 같지만 내용이 다른 파일이 있으면 확장자 앞에 `_출처자`를 붙인다. 그래도 충돌하면 `_출처자_2`, `_출처자_3` 순으로 번호를 붙인다.

정확히 같은 SHA-256 파일이 여러 곳에 있으면 한 파일만 복사하고 모든 원본 경로와 출처자를 `중복파일.csv`와 `분류목록.csv`에 기록한다. 동일 파일에 서로 다른 기존 주제가 지정된 경우에는 자동으로 하나를 고르지 않고 충돌 검토 대상으로 보낸다.

복사 시 가능한 경우 원본 수정 시각을 유지한다. 결과 목록은 주제, 미디어 종류, 촬영 시각, 파일명 순으로 정렬한다.

## 12. 보고서

`분류목록.csv`는 Excel과 편집 도구에서 쉽게 열 수 있도록 UTF-8 BOM 형식으로 기록하며 다음 열을 포함한다.

- 결과 주제
- 미디어 종류
- 촬영 시각
- 출처자
- 원본 파일명
- 원본 경로
- 결과 상대 경로
- 파일 크기
- SHA-256
- 분류 방식: 기존 폴더, 자동, 사용자 지정, 검토 보류
- 분류 신뢰 등급
- 최상위 대안 주제

`중복파일.csv`는 대표 복사본과 생략된 모든 동일 파일의 원본 경로를 기록한다. `처리오류.csv`는 처리 단계, 원본 경로, 오류 요약, 재시도 가능 여부를 기록한다.

`README_편집자용.txt`는 폴더 구조, 목록 열 설명, `검토필요` 의미와 Google Drive에서 원하는 주제만 내려받는 방법을 짧게 안내한다.

## 13. 복사, 검증, 재개

실제 복사 전 다음을 검사한다.

- 결과가 입력 폴더 내부가 아닌지
- 결과 경로가 기존 원본이나 다른 완료 결과를 덮어쓰지 않는지
- 계획된 고유 파일 크기와 여유 공간이 충분한지
- Windows 경로와 파일명이 유효한지
- 모든 검토 결정이 저장되었는지 또는 보류로 명시되었는지

파일은 임시 확장자로 대상 폴더에 복사한 뒤 SHA-256을 검증하고 최종 이름으로 원자적으로 변경한다. 해시 불일치나 읽기 오류가 발생하면 임시 파일을 남기지 않고 오류를 기록한다.

각 파일이 완료될 때 SQLite 상태를 커밋한다. 재시작 시 대상 파일의 크기와 해시를 재확인하여 완료 항목은 건너뛴다. `취소`는 현재 파일 복사를 안전하게 끝내거나 임시 파일을 제거한 뒤 중지한다.

## 14. 오류 처리

- 지원하지 않는 확장자: 복사하지 않고 오류 보고서에 기록
- 손상된 이미지: 분류 검토 대신 처리 오류로 기록
- 읽을 수 없는 영상: 원본 메타데이터와 오류를 기록하고 사용자가 미분류 복사를 선택할 수 있게 함
- 모델 초기 다운로드 실패: 원인을 표시하고 재시도 제공; 파일 작업은 시작하지 않음
- GPU 없음: CPU 모드로 자동 전환
- 디스크 공간 부족: 복사 전 중단
- 작업 중 공간 부족: 현재 임시 파일을 정리하고 재개 가능 상태로 중단
- 입력 파일 변경: 해당 파일의 분석과 승인을 무효화하고 재처리
- UI나 서버 종료: SQLite의 마지막 완료 지점에서 재개

오류 메시지는 원본을 변경하지 않았다는 사실과 사용자가 취할 수 있는 다음 행동을 함께 표시한다.

## 15. 개인정보와 보안

- 서버는 `127.0.0.1`에만 바인딩한다.
- 원본 이미지, 영상, 추출 프레임과 임베딩을 외부 서비스에 전송하지 않는다.
- 미리보기 캐시는 작업 전용 캐시 폴더에 두고 사용자가 삭제할 수 있게 한다.
- 로그에는 전체 이미지나 영상 내용을 넣지 않는다.
- Google Drive 공유 권한 설정은 프로그램 범위 밖이며, 결과 폴더 업로드 후 사용자가 읽기 전용 공유를 설정한다.

## 16. 테스트 및 실제 자료 검증

### 자동 테스트

- Unicode와 구분 기호를 포함한 폴더명 정규화
- 자동 통합과 검토 후보 구분
- 동일 해시 중복 검출
- 같은 이름·다른 내용의 파일명 충돌 해결
- 고신뢰도 및 저신뢰도 게이트
- 새 주제 생성과 일괄 승인
- 결과 경로가 입력 내부일 때 차단
- 공간 부족 사전 차단
- 복사 중단과 재개
- 복사 후 해시 검증 실패 처리
- CSV의 UTF-8 BOM과 정렬 순서

AI 모델이 필요한 테스트와 일반 로직 테스트를 분리한다. 일반 테스트는 모델 없이 가짜 특징 벡터와 임시 파일로 빠르게 실행한다.

### 실제 자료 검증

1. 기존에 분류된 파일 일부의 폴더명을 숨긴 뒤 원래 주제를 맞히는 교차 검증을 실행한다.
2. 자동 분류 기준을 통과한 파일의 오분류율과 검토 대기 비율을 보고한다.
3. 전체 275개 파일에 대해 복사 없는 미리보기 실행을 수행한다.
4. 사용자가 폴더명 통합과 저신뢰도 분류를 검토한다.
5. 실제 복사를 수행하고 원본·결과 해시를 전수 비교한다.
6. 결과 파일 수, 중복 생략 수, 보류 수, 오류 수의 합이 입력 파일 수와 일치하는지 확인한다.
7. 결과 폴더를 Google Drive에 폴더 업로드한 뒤 표본 폴더의 구조와 파일 수를 확인한다.

## 17. 배포와 사용 흐름

개발 중에는 명령 한 번으로 로컬 서버를 실행한다. 최종적으로는 Windows 사용자가 Python 명령을 몰라도 실행할 수 있는 실행 스크립트 또는 패키지 제공을 목표로 한다.

일반 사용 흐름은 다음과 같다.

```text
프로그램 실행
→ 수집 폴더 선택
→ 결과 위치 선택
→ 스캔 및 폴더명 검토
→ 자동 분석
→ 애매한 파일 검토
→ 복사 계획 승인
→ 복사 및 해시 검증
→ 편집자전달용 폴더를 Google Drive에 폴더 업로드
→ 영상 편집자에게 상위 폴더 읽기 권한 공유
```

## 18. 향후 확장

첫 버전이 안정화된 뒤에만 다음 기능을 검토한다.

- Google Drive API를 통한 원격 스캔과 업로드
- 카테고리별 선택 압축
- 편집용 프록시 영상 생성
- 연락처 시트 또는 영상 프레임 인덱스 생성
- 다른 행사 자료에 재사용할 수 있는 프로젝트 프리셋

이 확장 기능은 현재 구현의 성공 조건이 아니다.
